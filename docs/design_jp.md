# 名もなきあの遊び 設計書

この文書は、[`specifications_jp.md`](specifications_jp.md) を実装するための技術設計書である。画面表示やゲーム動作が本書と仕様書で食い違う場合は、仕様書を正とする。

現在は第1段階の設定保持、設定画面、ホーム画面と共通の起動・音声処理を実装している。第1・2章は現在の実装を記載し、第3〜8章は今後の実装計画とする。第9章では実装済みの音声監視と、プレイ画面追加時の方針を区別する。

本作は、次の順番で実装する。

1. 裏側の設定保持、設定画面、ホーム画面
2. プレイ画面（2人プレイ）
3. プレイ画面（1人プレイ・やさしい）
4. CPUの探索・分析
5. プレイ画面（1人プレイ・ふつう）
6. プレイ画面（1人プレイ・むずかしい）
7. ルール説明画面

後の段階で必要になる機能を先に作り込まない。各段階を単独で起動・確認・テストできる状態にしてから次へ進む。ただし、後続モードでも共有するゲームルールやプレイ画面の部品は、最初に必要となる段階で再利用可能な形にする。


## 1. 全体方針

### 1.1 責任の分離

- ゲームルールはFlutterに依存しない純粋なDartで実装する。
- Widgetは状態を表示し、ユーザー操作をNotifierへ渡すことに集中する。
- 設定保存、音声再生、時刻取得などの外部機能は専用クラスで包む。
- 画面とCPUは同じゲームルールを使い、指の計算や合法手判定を重複実装しない。
- CPUの強さと、画面上で手を選ぶ演出を分離する。

### 1.2 共通表示

画面は左右両方の横向きに固定し、`SystemUiMode.immersiveSticky` でシステムUIを隠す。`ThatNamelessGame` の `MaterialApp.builder` で、Navigatorを含む全画面の外側に1つだけ16:9の表示枠を置く。論理サイズは `1280 × 720` とする。

```dart
ColoredBox(
  color: Colors.black,
  child: Center(
    child: FittedBox(
      fit: BoxFit.contain,
      child: SizedBox(width: 1280, height: 720, child: currentScreen),
    ),
  ),
)
```

論理サイズ、BGM音量、画像ボタンの連打抑止時間は `AppConfig`、共通色は `AppColors`、日英の表示文字列は `AppStrings`、アセットパスは `Assets` に集約する。フォントは `Rwi` を使用する。画面内の座標や寸法は各Widgetに直接定義しており、`LayoutSpec` と `MotionSpec` は未導入である。

### 1.3 状態管理と画面遷移

状態管理にはRiverpodを使用する。Providerは「寿命」と「変更理由」が同じ情報だけをまとめる。

| 状態 | 寿命 | 管理先 |
|---|---|---|
| 言語、BGM、SE、2人プレイ制限時間、☆ | アプリ終了後も保持 | `appSettingsProvider` |
| BGM再生状態、音声へ適用するforeground状態 | アプリ起動中 | `audioControllerProvider` |
| 音声準備前からのアプリのforeground状態 | `Bootstrap` の生存中 | `AudioObserver` |
| 対局、選択、残り時間、結果 | プレイ画面を開いている間 | `playSessionProvider`（未実装） |
| ルールのページ番号 | ルール画面を開いている間 | `RulesScreen` 内部（未実装） |

画面は `Navigator` で遷移する。設定、プレイ、ルールはすべてホームを入口とする。アプリ再起動時は前回の画面を復元せず、必ずホームから開始する。

現在の遷移先は設定画面のみで、`PageRouteBuilder` の往復の遷移時間をゼロにして切り替える。`Bootstrap` は準備済みの設定リポジトリ、初期設定、音声管理を `ProviderContainer` に上書き登録し、`UncontrolledProviderScope` で画面へ渡す。コンテナと音声の破棄も `Bootstrap` が担当する。

### 1.4 現在のファイル構成

| ファイル | 責務 |
|---|---|
| `lib/main.dart` | 例外ハンドラ、横向き・全画面設定、テーマ、16:9表示枠 |
| `lib/config/config.dart`、`assets.dart` | 共通定数、文字列、音声の種類、アセット参照 |
| `lib/initialization/bootstrap.dart`、`image_preloader.dart` | 起動準備と画像先読み |
| `lib/settings/settings_state.dart` | 設定値とenum |
| `lib/settings/save_settings.dart` | 設定の読込・保存 |
| `lib/settings/update_settings.dart` | 設定変更、保存キュー、設定Provider |
| `lib/audio/audio_controller.dart`、`audio_observer.dart` | 音声再生とライフサイクル監視 |
| `lib/screens/home/home_screen.dart` | ホーム画面 |
| `lib/screens/settings/settings_screen.dart` | 設定画面 |
| `lib/screens/widgets/tappable_image.dart` | 連打と非同期処理中の重複操作を抑止する画像ボタン |


## 2. 第1段階：設定保持、設定画面、ホーム画面

この段階ではゲームを実装しない。起動、設定の読込、設定変更、音声、ホームへの復帰までを完成させる。モードボタンは後続段階で順に有効化する。

### 2.1 保存する設定

```dart
enum AppLanguage { jp, en }

class AppSettings {
  final AppLanguage language;
  final bool bgmEnabled;
  final bool seEnabled;
  final TimeLimit timeLimit;
  final bool star2p;
  final bool starEasy;
  final bool starNormal;
  final bool starHard;
}
```

初期値は、端末言語が日本語なら日本語、それ以外は英語、BGMとSEはON、2人プレイは15秒、☆はすべて未獲得とする。

`AppSettings` は不変オブジェクトで、`copyWith`、値の等価比較、`hasStar(StarMode)` を持つ。`TimeLimit` は5、10、15、20、30、45、60秒と無制限を表すenumで、無制限の保存値は `-1`、`duration` は `null` とする。`StarMode` は `twoPlayer`、`easy`、`normal`、`hard` を持つ。

`SettingsRepository` が `SharedPreferences` を包み、次のキーを管理する。

```text
settingsInitialized
language
bgmEnabled
seEnabled
twoPlayerTimeLimitSeconds
starTwoPlayer
starEasy
starNormal
starHard
```

言語は `.index` ではなく `jp` / `en` の文字列、制限時間は秒数の整数で保存する。`star2p` の保存キーは `starTwoPlayer` とする。未知の値、型違い、許可されていない制限時間は、その項目だけ初期値へ戻す。正常な項目は維持する。

`loadOrCreate` は `settingsInitialized` が `true` でなければ読み込んだ設定を保存する。保存時は各項目を書き込み、すべて成功してから初期化済みフラグを保存する。初期化済みの場合、欠損・不正値はログに記録し、読込時には保存値を書き直さない。保存APIが `false` を返した場合は例外として扱う。

### 2.2 起動処理

```text
1. 例外ハンドラを登録し、端末を横向き・全画面表示に設定する
2. BootstrapでAudioObserverを作り、アプリ状態の監視を始める
3. 保存済みAppSettingsを読み込み、未初期化なら設定を保存する
4. 全画面の静止画像と、BGM・全SEを並行して準備する
5. AudioObserver.attachで設定と最新のforeground状態を音声へ適用する
6. ProviderContainerを作成し、ホーム画面を表示する
```

設定読込中に初期言語や誤った☆を一瞬表示しない。初期化完了までは黒一色の専用起動画面を表示する。設定読込・初回保存・画像準備などで失敗したら「再試行」ボタンを表示する。ボタンの言語は読込済み設定に従い、設定読込前の失敗では英語とする。再試行の重複実行を防ぎ、起動失敗・Widget破棄時には準備済みの音声やコンテナを破棄する。

`preloadAllImages` は `AssetManifest` に登録された `assets/home/`、`assets/settings/`、`assets/play/`、`assets/rules/` 配下のPNG・JPEG・WebPを、両言語とも最大4枚ずつ並行して先読みする。GIFは対象外とする。画像キャッシュ容量は最低128 MiBに広げ、ホーム・設定背景は `Assets.image` を通じて1280×720でデコードし、表示時も同じキャッシュキーを使う。

個別処理で扱わない未処理例外は、Zone、Flutterフレームワーク、ルートIsolateのハンドラから `AppExit.onUncaughtError` へ渡し、`SystemNavigator.pop` を一度だけ要求する。

### 2.3 設定変更

`AppSettingsNotifier` は言語、BGM、SE、制限時間の変更と、モード別の☆解除を公開する。設定画面に保存ボタンは設けず、タップ時に表示へ即時反映して保存する。保存処理は直列化し、連続変更で古い値が最後に保存されることを防ぐ。

同じ値への変更では保存しない。保存失敗時も現在の表示値を維持してエラーをログへ記録し、後続の保存処理を継続する。専用の再試行UIや自動再試行はなく、次の設定変更で最新の設定全体を保存する。BGMとSEの変更は音声管理にも即時反映する。

☆を消す `clearStar` は実装済みだが、画面からはまだ呼び出していない。☆の獲得・結果確定時の保存APIはプレイ画面の段階で追加する。

### 2.4 音声

- BGMは、設定がONかつアプリがforegroundのときだけループ再生する。
- BGMをOFFにしたら一時停止し、ONに戻したら保持位置から再開する。
- SEがOFFなら効果音を開始しない。
- 通常SEはBGMを止めない。
- 勝敗SEの間だけBGMを止め、終了後に条件を満たせば再開する。
- `AppLifecycleState.resumed` 以外ではBGMを一時停止し、新しいSEの再生を抑止する。再生中のSEを途中停止する処理はない。SEの設定をOFFにした場合も新規再生の抑止のみ行う。

BGMと8種類のSEはホーム表示前に、それぞれ専用の `AudioPlayer` へソースを設定する。BGMは音量0.5・ループ、SEは再生完了時に停止する設定とし、再利用する。音声コンテキスト設定の失敗は無音の管理クラスへ切り替え、個別音声の読込失敗はその音声を除外して起動を続ける。他アプリの音楽と共存するよう、Androidでは音声フォーカスを要求せず、iOSでは `mixWithOthers` を指定する。

プレイヤー操作はキューで直列化し、BGMの状態が変わらない場合は再操作しない。通常SEは先頭から再生する。結果音用の `playResult` は重複実行を抑止し、BGMを一時停止して再生完了を待ち、終了後に最新の設定とforeground状態で再開可否を判定する。SEが無効・未準備なら完了待ちを省く。破棄要求後は未実行操作を捨て、結果音の完了待ちも解除する。

### 2.5 ホーム画面

ホームは背景、タイトル、4モードのボタンと☆、ルール、設定ボタンを `Stack` で表示する。言語と☆は `appSettingsProvider` から受け取り、ホーム自身はゲーム状態を持たない。

現在は設定ボタンだけが画面遷移とタップSEを実行する。4モードとルールのボタンは表示されるが、タップ時は未実装である旨を `debugPrint` へ出力するだけで、画面上の「準備中」表示やSEはない。

画像ボタンは共通の `TappableImage` を使う。ボタンごとにタップ後500 msと非同期コールバックの完了まで重複操作を抑止する。設定を開くコールバックは `Navigator.push` を待つため、設定画面を閉じるまで再実行されない。波紋・ハイライト・ホバー色は表示しない。

### 2.6 設定画面

2人プレイ制限時間、SE、BGM、言語を変更できる。表示は常に `appSettingsProvider` から作り、編集中コピーを持たない。言語変更は画面内の文字にも即時反映する。端末の戻る操作と画面内ホームボタンは、どちらもホームへ戻る。

選択肢は `GestureDetector` で操作する文字ベースのWidgetで、画像ボタンの500 msの連打抑止は適用しない。選択済み項目をタップしても設定の再保存は行わない。

### 2.7 完了条件

- 初回起動時に正しい初期値でホームが表示される。
- 設定変更後に再起動しても値が保持される。
- 日本語と英語、BGMとSEのON/OFFが即時反映される。
- バックグラウンド復帰で音声が重複再生されない。
- 16:9外の領域が黒く表示される。


## 3. 第2段階：プレイ画面（2人プレイ）

この段階でゲームルールとプレイ画面の共通部分を作る。CPUはまだ作らない。

### 3.1 ゲームモデル

```dart
enum PlayerSide { near, far }
enum HandPosition { left, center, right }

class GamePosition {
  final List<int> nearHands;
  final List<int> farHands;
  final PlayerSide turn;
}

class GameMove {
  final HandPosition attackerPosition;
  final HandPosition targetPosition;
}

class GameSession {
  final GamePosition position;
  final Set<PositionKey> visitedPositions;
}
```

各プレイヤーは左・中央・右の3本を持ち、値は0〜4とする。`0` の手は攻撃にも対象にも使えない。位置はループ判定に含むため、同じ指の組合せでも並べ替えない。`PositionKey` には6本と手番を含め、初期盤面も履歴へ登録する。

### 3.2 ゲームルール

```text
攻撃後 = (攻撃側の指 + 対象側の指) % 5
```

1ターンは、合法性検査、対象更新、手番交代、全滅判定、交代後盤面のループ判定、履歴追加の順で処理する。ループ時は残存指合計が少ない側を勝ちとし、同数なら引き分けとする。

```dart
enum GameEndReason { eliminated, timeout, loop }
enum GameOutcome { nearWin, farWin, draw }
```

`GameEngine` は `legalMoves`、`isLegalMove`、`applyMove` を公開する。UIは独自にルールを計算しない。

### 3.3 初期盤面

仕様書の52組から均等に1組を選び、両者の並び順、手前・奥への割当、先攻をそれぞれランダムに決める。乱数生成器は外から渡せるようにする。52組の範囲外や、初手で0を作れる組を生成しないことをテストする。

### 3.4 プレイ状態と画面

```dart
enum PlayPhase {
  countdown,
  selecting,
  attacking,
  confirmingExit,
  finished,
}
```

状態はモード、対局、phase、選択中の2本、残り時間、結果、保留中の攻撃を持つ。非同期処理には `operationId` を付け、画面離脱や再戦後に返った古い通知を無視する。

プレイ画面は、背景、両者の手、手番、残り時間、けってい、ホーム、攻撃アニメーション、カウントダウン、終了確認、結果を1つの `Stack` で表示する。モーダル中は背後への入力を遮断する。

「けってい」では期限切れを先に確認する。合法手なら結果を保留してアニメーションを開始し、衝突時に盤面表示を更新する。勝敗表示または次ターンへの移行はアニメーション完了後に行う。

### 3.5 タイマー

`Timer.periodic` の回数ではなく期限 `deadline` を保持する。

```text
remaining = max(Duration.zero, deadline - clock.now())
```

時刻は差し替え可能な `Clock` から取得する。両者に設定時間をターンごとに与え、無制限ではdeadlineを作らない。バックグラウンド時間も現在の手番の制限時間に含め、復帰時に超過していれば時間切れとする。

### 3.6 終了と☆

プレイ中のホーム操作と端末の戻る操作では、対局を破棄するか確認する。途中終了では☆を付けない。勝敗または引き分けまで到達したら2人プレイの☆を未確定にし、結果画面で「ホーム」または「もう一度」を選んだ時点で保存してから遷移する。

### 3.7 完了条件

- 2人が交互に操作し、全滅、ループ、時間切れで終了できる。
- カウントダウン、攻撃、終了確認、結果、再戦が正しく遷移する。
- バックグラウンド時間が現在の手番へ反映される。
- 対局完了後に2人プレイの☆が保存される。
- mod 5、合法手、履歴、初期盤面、勝敗、タイマー競合を自動テストできる。


## 4. 第3段階：プレイ画面（1人プレイ・やさしい）

2人プレイ画面を複製せず、同じ `PlayScreen` と `PlaySessionNotifier` をモードによって動作させる。

### 4.1 CPUの導入

人間の手番だけ入力を許可する。やさしいモードの人間側制限時間は30秒とする。CPU手番中も時間を表示するが、バックグラウンド中はCPU処理を止め、復帰後に再開する。バックグラウンド時間でCPUを時間切れにしない。

```dart
abstract interface class CpuStrategy {
  GameMove chooseMove(GameSession session, Random random);
}
```

CPUは必ず `GameEngine.legalMoves` から手を選び、人間と同じ `applyMove` で確定する。

### 4.2 やさしいCPU

- 相手の手を直ちに0にできる合法手があれば、95%の確率でその中から選ぶ。
- 残り5%、または該当手がなければ、全合法手からランダムに選ぶ。
- 同条件の候補が複数あれば乱数で選ぶ。
- 深読み、minimax、事前テーブルは使用しない。

### 4.3 操作演出

戦略による決定と画面上の待ち時間を分ける。`CpuScheduler` が4〜10秒の範囲で「攻撃側を選ぶ、1秒以上空ける、対象を選ぶ、1秒以上空ける、けってい」を演出する。やさしいCPUは選び直さない。

画面離脱、再戦、バックグラウンド移行時には古いスケジュールを無効化する。

### 4.4 結果と完了条件

人間勝利時だけ、やさしいモードの☆を未確定にする。敗北と引き分けでは付けない。

- 2人プレイを壊さず、同じ画面で人間対CPUを実行できる。
- CPUが常に合法手を返し、95%分岐を注入した乱数で検証できる。
- 演出が4〜10秒、各操作1秒以上を満たす。
- CPU手番中のバックグラウンド時間を加算しない。
- 人間勝利後にやさしいの☆が保存される。


## 5. 第4段階：CPUの探索・分析

この段階では、ふつう・むずかしい画面をまだ有効化しない。Pythonで状態空間を調査し、後続CPUの方式を数値に基づいて確定する。

### 5.1 探索対象と評価

指6本と手番だけなら最大 `5^6 × 2 = 31,250` 盤面だが、ループ評価は到達履歴にも依存する。盤面だけの表を完全な対局状態と同一視しない。探索中も `visitedPositions` を引き継ぎ、既出状態への到達をループ結果として評価する。

CPU側から見て、勝ち・引き分け・負け、決着手数、残存指合計、ループ結果を区別する。基本比較は「早い勝ち、遅い勝ち、有利な未確定、引き分け、不利な未確定、遅い負け、早い負け」の順とし、最終的な重みは分析結果で決める。

### 5.2 Python探索ツール

Python側にもDartと同じ初期盤面、合法手、攻撃、全滅、ループ判定を実装し、固定局面とランダム局面で結果を照合する。

探索結果には次を残す。

- 到達可能な盤面数と対局状態数
- 初期盤面ごとの勝敗傾向
- 深さごとの探索時間、展開数、枝刈り率
- 同評価候補の数
- 事前テーブルのサイズと読込時間
- 代表局面の推奨手と根拠

成果物は `tools/solver/`、そのテスト、`docs/cpu_analysis_jp.md` とする。バイナリが必要な場合のみ `assets/data/cpu_table.bin` を生成する。形式バージョン、状態・手・評価値の符号化を文書化し、PythonとDartの一致テストを作る。

### 5.3 完了条件

- PythonとDartのルール判定が一致する。
- ふつうCPUの探索深さ、評価関数、時間上限を決定できる。
- むずかしいCPUの事前テーブルと実行時探索の役割を決定できる。
- 結果と測定環境を `cpu_analysis_jp.md` に残し、再測定できる。


## 6. 第5段階：プレイ画面（1人プレイ・ふつう）

第4段階の結果をもとに `NormalCpu` を実装し、ふつうモードを有効化する。

- 深さ制限付きminimaxとαβ枝刈りを基本とする。
- 探索深さ、ノード上限、時間上限は分析結果を定数化する。
- 末端は勝敗、残存指合計、合法手数など分析で決めた関数で評価する。
- 同評価の最善手が複数あればランダムに選ぶ。
- 現在の履歴を渡し、探索中の即時ループを評価する。

人間側制限時間は15秒とする。CPUは3〜8秒で選択と決定を行い、各操作の間隔は0.5秒以上とする。15%の確率で1ターンに1回だけ選び直す。選び直しは演出であり、最終確定手は `NormalCpu` の結果と一致させる。

完了条件は、対象端末で探索上限内に安定して手を返すこと、代表局面でやさしいより先を読むこと、演出時間を守ること、人間勝利後にふつうの☆が保存されることとする。


## 7. 第6段階：プレイ画面（1人プレイ・むずかしい）

第4段階の成果を使って `HardCpu` を実装し、むずかしいモードを有効化する。

- 事前評価テーブルは候補の並べ替えと基本評価に使う。
- 現在の履歴を加味する実行時探索で最終手を決める。
- テーブルだけで履歴依存のループ結果を確定しない。
- 推奨手が現在の履歴で不利なループを起こす場合は別の手を選ぶ。
- 「ほぼ最強」だが、全パターンを理解した人間に勝機を残す調整値は定数管理する。

人間側制限時間は5秒とする。CPUは1〜4秒で選択と決定を行い、各操作の間隔は0.25秒以上とする。15%の確率で1ターンに1回だけ選び直す。

完了条件は、代表局面と多数対局で狙った強さを確認すること、履歴依存ループを誤評価しないこと、Python/Dartの符号化が一致すること、人間勝利後にむずかしいの☆が保存されることとする。


## 8. 第7段階：ルール説明画面

全モード完成後にルール説明画面を追加し、ホームのルールボタンを有効化する。

```text
RulesScreen / Stack
├── PageView（1〜8ページ）
├── home（左上）
├── back_page（1ページ目では非表示）
└── next_page（8ページ目では非表示）
```

現在の言語に対応する1ページ目から開始する。矢印タップとスワイプは同じページ変更処理を使う。ホームへ戻ったらページ番号を破棄し、再入場時も1ページ目から開始する。

静止画とGIFは縦横比を維持する。GIFが重い場合は、解像度・フレーム数・色数の調整、非表示ページの解放、静止画とFlutterアニメーションによる再現、の順で対応する。

完了条件は、日本語・英語とも8ページを正しく表示できること、先頭と末尾の矢印制御、スワイプとの同期、再入場時の初期化、対象端末でのGIF負荷確認とする。


## 9. 共通のライフサイクル規則

現在は `Bootstrap` が `AudioObserver`（`lib/audio/audio_observer.dart`）を1つ所有する。`AudioObserver` は `WidgetsBindingObserver` を使い、生成時の `lifecycleState` とその後の変化を追跡する。音声準備前の状態変化も保持し、`attach` 時に保存設定とともに適用する。`resumed` のときだけforegroundとみなし、破棄時に監視登録を解除する。

プレイ状態への通知は未実装である。プレイ画面を追加する段階で、以下の規則に従う監視・通知を実装する。

| 状態 | バックグラウンド移行時 | 復帰時 |
|---|---|---|
| プレイ画面外（実装済み） | BGMを一時停止、新規SEを抑止 | 設定と結果音の再生状態に従いBGMを再開 |
| countdown | 残り演出時間を保持 | 残りから再開 |
| 人間の手番 | deadlineを保持 | 経過時間を含めて期限判定 |
| CPUの手番 | CPU演出を停止 | バックグラウンド時間を除いて再開 |
| attacking | アニメーションを停止 | 保留結果を一度だけ確定 |
| confirmingExit | そのまま保持 | そのまま表示 |
| finished | 結果を保持 | 結果を表示 |

プロセス自体が終了した場合、対局は保存・復元しない。次回起動時は保存済み設定だけを読み込み、ホームから開始する。
